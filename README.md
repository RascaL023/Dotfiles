# Dotfiles

Personal Linux dotfiles: every config lives in this repo (`~/.dotfile`) and is
symlinked back into `~/.config/<tool>`. One repo, one source of truth, no
drift between machines.

The theming layer ([matugen](https://github.com/InioX/matugen)) lives in
[`matugen/`](matugen) and paints every tool from a single color source — either
a wallpaper or a hand-written palette.

> **No compositor lock-in.** The repo ships a `hypr/` config because that is what
> is being used right now, but nothing in it, in the sync script, or in the
> theming pipeline depends on Hyprland. Any Wayland/X11 setup works.

---

## Repository layout

```text
~/.dotfile
├── .synchronizer/          # the link/restore/status script + local state
├── tools.list              # which tools the synchronizer manages
├── matugen/                # theming engine: configs, templates, palettes
│   ├── config.toml         #   wallpaper-derived theme (Material You)
│   ├── templates/
│   │   ├── general/        #   templates for the wallpaper flow
│   │   └── kanagawa-dragon-lotus/
│   │       ├── blueprint/  #   hand-written palette JSON (see its README)
│   │       ├── template/   #   templates for the fixed palette
│   │       └── config.toml #   renders the fixed palette
│   └── docs/               # documentation (start at docs/README.md)
├── hypr/                   # compositor config (Lua)
│   └── docs/               #   backlog fitur 0.56 yang belum dipakai
├── nvim/ kitty/ foot/ alacritty/ …   # one directory per tool
└── AGENTS.md               # rules for AI agents working in this repo
```

## Included configs

The authoritative list is [`tools.list`](tools.list); this table explains what
each entry is.

| Tool | What it is | Themed by |
|---|---|---|
| `kitty` | GPU terminal emulator | both flows (`kitty/theme.conf`) |
| `foot` | Lightweight Wayland terminal | both flows (`foot/theme.ini`)¹ |
| `alacritty` | GPU terminal emulator | both flows (`alacritty/theme.toml`) |
| `cava` | Audio visualizer | — |
| `hypr` | Hyprland compositor | — |
| `waybar` | Status bar | wallpaper flow, GTK CSS (`css/theme.css`) |
| `eww` | Widget system | wallpaper flow, SCSS (`scss/theme`) |
| `wlogout` | Logout menu | wallpaper flow, GTK CSS (`css/theme.css`) |
| `rofi` | App launcher | both flows (`rasi/theme.rasi`) |
| `nvim` | Neovim editor | both flows (`nvim/theme.lua`) |
| `yazi` | Terminal file manager | both flows, colors only (`yazi/flavor.toml`)² |
| `lazygit` | Terminal Git UI | both flows (`lazygit/config.yml`) |
| `herdr` | Terminal multiplexer | both flows (`herdr/config.toml`) |
| `matugen` | The theming engine itself | — |

"Both flows" = the file is regenerated by either the wallpaper pipeline or the
fixed-palette pipeline; see [Theming](#theming).

¹ `foot/foot.ini` loads its palette with
`include=/home/rascal/.myenv/theme/current/foot/theme.ini`, so it follows the
active theme the same way `kitty/kitty.conf` does. Flow A writes
`generated/live.bak/foot/theme.ini`, Flow B
`generated/kanagawa-dragon-lotus/foot/theme.ini`; foot sees whichever one the
active theme exposes. Foot has no reload signal, so a re-render only shows up in
the next foot window.

² `yazi/theme.toml` is static on purpose and small (~40 lines: border symbol,
tab separators, `which` columns, notify/cmp icons) — the 43 KB icon table now
lives in the ignored `yazi/theme.toml.bak`. The generated files are the color
flavor and the preview tmTheme, both reachable inside the same flavor directory:
`~/.config/yazi/flavors/matugen.yazi/flavor.toml` and
`.../tmtheme.xml` → `~/.myenv/theme/current/yazi/`.

## Synchronizer

All repo↔`~/.config` plumbing goes through
[`.synchronizer/.sync.sh`](.synchronizer/.sync.sh) (pure bash). It **moves** the
real config into the repo and leaves a symlink behind — it never copies.

### Interactive

```bash
bash ~/.dotfile/.synchronizer/.sync.sh
```

Asks for the password (`atmin123`, hardcoded, 3 attempts), then shows a menu:

```text
1. Start linkings    # move configs into the repo and symlink them back
2. Restore links     # undo: move configs back to their original location
3. Status            # dry-run report; changes nothing
4. Clear
0. Exit
```

Options 1–3 then ask:

```text
Target (kosong = semua):
```

Leave it empty for **all** tools, or type one or more names separated by spaces
(`cava foot hypr`).

### Non-interactive

```bash
~/.dotfile/.synchronizer/.sync.sh <command> [tool ...]
```

| Command | Example | Effect |
|---|---|---|
| `link` | `sync.sh link` | link every tool |
| `link` | `sync.sh link cava` | link one tool |
| `link` | `sync.sh link cava foot` | link several tools |
| `restore` | `sync.sh restore hypr` | move a tool back to its origin |
| `status` | `sync.sh status` | report every tool |
| `status` | `sync.sh status cava` | report one tool |

The CLI path skips the password prompt.

Error messages (verified by running them):

| Situation | stderr | Exit |
|---|---|---|
| unknown command | `[ERR] Unknown command: <cmd> (use: link\|restore\|status [tool ...])` | `1` |
| unknown tool | `[ERR] unknown tool: <name> (not in tools.list)` | `0` — the remaining tools are still processed |
| config missing / cannot be moved | `[ERR] <tool>: <reason>` (e.g. `source not found`) | `0` |

### Status states

| State | Meaning |
|---|---|
| `LINKED` | target is a symlink pointing into `~/.dotfile` — all good |
| `STAGED (not linked)` | config is already in the repo, symlink not in place yet |
| `NOT LINKED` | still the original config in `~/.config` |
| `MISSING` | not found in the repo or in `~/.config` |

### State file

`.synchronizer/state.tmp` records `tool<TAB>original path` for each linked tool,
so `restore` can put a config back even when it does not live under `~/.config`.
It is local, machine-specific, and git-ignored (`**.tmp`).

### `tools.list` format

Blank lines and `#` comments are ignored. One tool per line:

```text
# name          → auto-locate under $XDG_CONFIG_HOME (default ~/.config)
kitty
hypr

# name:path     → use an explicit path (may be outside XDG, ~ allowed)
lazygit:~/.config/lazygit
```

Two entries already use the explicit form (`lazygit`, `herdr`); the rest are
auto-located by name.

## Theming

Source of truth: [`matugen/`](matugen) (symlinked as `~/.config/matugen`).

```text
        ┌─ wallpaper ─► matugen image ─┐
color ──┤                              ├─► template ─► ~/.myenv/theme/generated/…
        └─ blueprint ─► matugen json ──┘                      │
                                                              ▼
                                              ~/.myenv/theme/current  ◄─ symlink
                                                              │
                                          kitty, foot, alacritty, waybar, wlogout,
                                          rofi, eww, nvim, yazi, …
```

`~/.myenv` is the theme store **outside** this repo; the repo only renders into
it. `current` is a symlink to one theme directory and is flipped by
`~/.myenv/script/theme/theme-switcher.sh` (not part of this repo).

### Flow A — wallpaper-derived (Material You)

```bash
matugen image <wallpaper> --source-color-index 0 -c ~/.config/matugen/config.toml
```

- Config: `matugen/config.toml`
- Templates: `matugen/templates/general/*`
- Vocabulary: `{{ colors.<role>.<scheme>.<format> }}` (MD3 roles: `primary`,
  `surface`, `on_surface`, …)
- Output: `~/.myenv/theme/generated/live.bak/<tool>/…`

### Flow B — fixed palette (a named theme)

```bash
matugen json matugen/templates/kanagawa-dragon-lotus/blueprint/kanagawa-dark.json \
  -c matugen/templates/kanagawa-dragon-lotus/config.toml
```

- Palette: `matugen/templates/kanagawa-dragon-lotus/blueprint/*.json` —
  hand-authored, **one file per variant** (`kanagawa-dark.json`,
  `kanagawa-light.json`)
- Templates: `matugen/templates/kanagawa-dragon-lotus/template/*`
- Vocabulary: the JSON is exposed at the template root, so templates read
  `{{ accent.primary }}`, `{{ syntax.keyword }}`, … — never `colors.*`
- Output: `~/.myenv/theme/generated/kanagawa-dragon-lotus/<tool>/…`
- Full key-by-key reference: [`blueprint/README.md`](matugen/templates/kanagawa-dragon-lotus/blueprint/README.md)

> Keep the two flows in **separate config files**. Templates from Flow B fail
> under `matugen image` (no `accent.*`), and Flow A's `colors.*` does not exist
> under `matugen json`.

### Who reads the generated files

| Consumer | Reads |
|---|---|
| `kitty/kitty.conf` | `~/.myenv/theme/current/kitty/theme.conf` |
| `alacritty/alacritty.toml` | `~/.myenv/theme/current/alacritty/theme.toml` |
| `waybar/style.css`, `wlogout/source.css` | `~/.myenv/theme/current/css/theme.css` |
| `rofi/themes/*.rasi` | `~/.myenv/theme/current/rasi/theme.rasi` |
| `eww/eww.scss` | `~/.myenv/theme/current/scss/theme` |
| `nvim/lua/core/theme.lua` | `~/.myenv/theme/current/nvim/theme.lua` |
| `foot/foot.ini` | `~/.myenv/theme/current/foot/theme.ini` |
| `yazi/flavors/matugen.yazi/flavor.toml` | `~/.myenv/theme/current/yazi/flavor.toml` (symlink) |
| `yazi/flavors/matugen.yazi/tmtheme.xml` | `~/.myenv/theme/current/yazi/tmtheme.xml` (symlink) |

`nvim/lua/core/theme.lua` maps the generated palette onto TokyoNight keys and
owns every plugin highlight group; when the generated file is missing it falls
back to plain TokyoNight and warns. See
[`matugen/docs/NVIM_MAPPING.md`](matugen/docs/NVIM_MAPPING.md).

## Setup on a new machine

```bash
git clone <repo-url> ~/.dotfile
bash ~/.dotfile/.synchronizer/.sync.sh link
```

Then make the theme available, since generated files are not committed:

```bash
# wallpaper theme
matugen image <wallpaper> --source-color-index 0 -c ~/.config/matugen/config.toml

# or the fixed palette
matugen json ~/.dotfile/matugen/templates/kanagawa-dragon-lotus/blueprint/kanagawa-dark.json \
  -c ~/.dotfile/matugen/templates/kanagawa-dragon-lotus/config.toml
```

Requires `matugen` (4.x) on `PATH` and a `~/.myenv/theme` store with a `current`
entry.
